# 次回Solへの引き継ぎ：盤面から次の楽しみが生まれるイベント

2026-10-20。ユーザーから「この設計案を次回Solにやらせるので分かりやすくメモ」と依頼された記録。
**この文書の新機能は未実装。今回実装するのは既存キャラクターのセリフ改善だけ。**
数値は以下で「試作値」と記したものを調整対象とする。過去の会話で指定された通常抽選確率を勝手に置き換えない。

## 目標と実装順

「ボールを落とす → 冒険が進む → 盤面に報酬が増える → 次のものを落としたくなる」という循環を作る。抽選の段数や待ち時間を増やすこと自体を目標にしない。

1. 地図進行：短期・中期の目標を見える形にする。
2. タワー内の宝玉：タワーの出現、崩壊、その後の回収まで楽しめるようにする。
3. ゴールドラッシュ：当選が目に見える盤面の動きになる。
4. 既存の航路選択を整理する。別の選択画面を重ねない。
5. JPの惜敗救済と球の挙動を検証する。現行救済との重複を先に決める。

先に1〜3を作り、実プレイで回転率と報酬量を確認してから4〜5を進める。

## 現在あるもの（実装前にコードで再確認）

- ミニボール回収で盤面へ10枚。さらに配達先を選び、同じ航路のスタンプ3個で専用チャレンジとJP準備アイテム。
- 大きいボール3個、通常イベントのJP抽選当選からJPへ進む。
- JPは航路決定 → 改装 → 最終10穴抽選。JP穴1〜5、30枚穴2、残り10枚穴。準備アイテムは灯り・航海図・補強。
- JP最終抽選で3回失敗すると次回のJPを＋1で開始する救済がある。
- タワーは120枚の独立剛体。床リフトで既存メダルを押しのけて出現する。
- JP球は外周斜面を高速周回し、減速して穴へ落ちる。2026-10-19公開版では100試行で平均約4.55周、入賞まで約7.25〜8.20秒。

主な入口：`src/game.ts`（進行・払出し・保存）、`src/events/challenge.ts`（航路と抽選）、`src/events/jp.ts`（JP）、`src/events/draw.ts` / `draw-view.ts`（物理抽選・表示）、`src/events/theater.ts`（演出）。物理盤面と保存の実装場所は検索してから変更する。

## 1. ミニボールで宝の地図を完成

提案：ミニボール1個で地図1マス。3マスでキャラクターの冒険イベント、6マスでJP挑戦。10枚の盤面払出しは維持。6到達で地図を次の周へ進め、余剰進行を失わない。

既存の「航路別スタンプ3個」と独立して二重報酬を出すと過剰になる。**推奨は地図へ統合**し、3マス地点を現在の航路チャレンジに対応させる。旧スタンプ3種は合計を引き継ぐが、既に獲得した報酬を再交付しない。合計6以上の旧データの扱いは、報酬履歴と突き合わせて移行ルールを明文化してから実装する。

- イベント画面の固定枠に6マス地図と「あと何個で何が起きるか」を常設。盤面へ被せない。
- 3マス目は短い冒険＋航路報酬、6マス目はJP権を1件予約。同じマスで複数の長い演出を積まない。
- 同時落下、イベント中の回収でも進行は即保存。演出は保留できるが報酬を重複しない。
- ミニボールの供給頻度が高いため、6個でJPは暫定値。既存の大球ルートも含め、JP頻度が過剰なら必要個数を調整する。

## 2. コインタワーの中から宝玉

提案：タワーに通常球・ミニボールと見分けられる宝玉を1個仕込む。タワー出現や崩壊では付与せず、**宝玉が手前の回収境界を越えた時だけ**報酬にする。

- 宝玉を入れられる内部空間をタワーに設ける。メダルと初期貫通させない。
- リフトで既存メダルを押しのける現行動作を保つ。空き地を作らない。
- 崩壊で宝玉が露出し、その後は通常の物理計算で転がり、押して手前へ運べる。
- 試作報酬はゴールドラッシュ1回。JP直撃と重ねず、盤面でご褒美が続く役割にする。
- 崩壊判定は演出だけに利用。報酬判定は宝玉の一意ID＋回収済み状態で一度限り。
- 盤面外へ不正脱落した際は未回収として再供給予約するなど、消失と二重取得の両方を防ぐ。

## 3. ゴールドラッシュ

提案：プッシャー20往復の間、報酬口からメダルが断続的に流れ、途中でミニボールも加わる。

試作値：開始後の各往復に3枚、計60枚。5往復・15往復時にミニボールを1個ずつ、計2個。通常イベント表にはまだ追加せず、まず宝玉回収からだけ開始する。

- 秒数ではなく完了した往復数で進行。報酬払出し中のプッシャー保持時間を往復と数えない。
- メダルは上段左の報酬口、ミニボールは既存の下段供給口。手持ちへの直接加算は禁止。
- 自動投入・手動投入・盤面の物理動作は継続。残り往復数を固定モニター内に表示。
- 盤面容量や射出待ちで遅れた分も払出し債務として保持する。ラッシュ終了で未払いを捨てない。
- 重複獲得はラッシュ権を予約し、現在の終了後に開始。無制限の同時射出やタイマー上書きをしない。
- 再読み込み、設定中断、非表示復帰で残り往復数・未払い・追加球の進行を復元する。

## 4. 冒険の行き先を選ぶ

原案の「港＝メダル／遺跡＝タワー／天文台＝JP強化」は役割の例。既存世界観と背景を活用し、**海路＝メダル／工房＝タワー／灯台＝JP強化**へ対応させるのが推奨。

現在のミニボール配達先選択をこの選択に統合する。選択前に報酬傾向を明示し、未操作時の既存自動選択も保つ。報酬の種類を変えても長期の価値が極端に偏らないよう調整する。「同期待値」は未検証なので断定しない。タワー120枚、JP準備、物理回収率を含めて比較する。

## 5. JPの惜敗と最後まで読めない動き

### 隣の穴に入った時のリベンジ（候補）

最終抽選でJP穴のすぐ隣に入ったら、次回だけJP穴＋1を予約する。複数のJP穴に隣接しても1回だけ。実際の最終ラベル配列と円周の両隣（0と9も隣）で判定する。航路球・改装球には適用しない。

既存の3回失敗救済がある。推奨試作は「3回失敗または隣穴で次回＋1」とする共通の救済1枠で、同時成立でも＋2にしない。上限5マス・アイテム消費時期・満杯時の繰越を先に定義する。惜敗を偽装する球の誘導はしない。

### 球の物理と演出

- 高速外周 → 内側へ移動 → 穴の縁で跳ねる／通過 → 実際の入賞という流れ。
- 現行を基準に穴の縁形状・傾斜・反発を調整し、「止まりそうで止まらない」終盤を作る。単に時間を延ばさない。
- 結果を先に決めて球を当たり穴へ誘導しない。照明と効果音も球の実際の位置に反応する。
- 入賞確定前に結果名・当選キャラ・確定音を出さない。見た目の穴と判定を一致させる。
- JP時の短い静止は演出画面だけ。盤面と投入を停止しない。続く大量払出しこそ見せ場にする。
- 全10穴への到達、決着時間、失速、飛び出し、復元を検証。物理結果の分布は穴数だけで公平と断定せず実測する。

## 共通の制約と完了条件

- イベント40%／盤面60%をすべてのイベントで固定。拡大縮小ボタンや自動サイズ変更を復活させない。
- 手前だけで回収。横落ちを作らない。イベント中も盤面と投入を継続する。
- 保存データに版管理を付け、旧セーブから移行する。予約済み報酬・抽選・払出しを失わない。
- 同時回収・再読み込み・保留列・ラッシュ中のJP等を確認し、二重報酬を防ぐ。
- 通常／地図／宝玉／ラッシュ／大球／JPを含めた報酬量とイベント待ち時間を計測する。固定シードの自動計測に加え、実プレイで「あと何を狙うか」が分かるか確認する。
- スマホ縦・横で背景全体、吹き出し、球、残り進捗が見えるか確認する。
- 新しい背景・宝玉・ポーズが必要なら制作対象を一覧にする。仮素材を完成品として扱わない。
- セリフは `DIALOGUE_DIRECTION.md` に従う。残り1個などの状況セリフは実状態を条件にし、汎用待機会話で誤った実況をしない。
